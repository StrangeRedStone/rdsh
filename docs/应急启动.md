# 应急启动卡 —— rdsh 不在 / 坏了时怎么办

> rdsh 是**便利层**，不是唯一启动路径。dsh 本体与数据 home 都在磁盘上，任何时候都能手工起。
> 本卡刻意不依赖 rdsh 可运行。

## 1. 先找"数据 home"（三条路，任一条可用即可）

```bash
# ① 命令还能跑
rdsh base

# ② 看状态账本：最后几列是 dir|data
sed -n '1,12p' ~/Mapp/.dsh-suite/state/versions.kv

# ③ 看检出里的回声（key= 就是对象键，数据 home = ~/Mapp/.dsh-suite/data/<key>）
sed -n '1,12p' ~/Mapp/dsh/<检出目录>/.installed
```

数据 home 的默认位置：`~/Mapp/.dsh-suite/data/<对象键>`（键见 `versions.kv` 的 `key` 列）。

## 2. 裸启动（不需要 rdsh）

```bash
cd <检出目录>                      # 例如 ~/Mapp/dsh/deepseek-harness-dsh-0.1.7-rc.2
DSH_HOME=<第 1 步找到的数据 home> pnpm dsh web --port 3080
# 端口被占就换一个；加 --no-open 不自动开浏览器
```

**裸启动比 rdsh 少了这四件事**（所以平时别裸启动）：

| 少了什么 | 后果 |
|---|---|
| 注入 `DSH_HOME` | **落到 dsh 默认 home → "找不到自定义的数据目录"**（会话/设置看起来全空） |
| `ensure_data_home` | 首启播种、稳定根资产软链没建 |
| `ensure_built` | 依赖没装/没构建，起不来 |
| `registry_put` | 起来了也不在 rdsh 视野里（`rdsh status`/`stop` 不认得它） |

## 3. 把 rdsh 装回来 / 修好入口

```bash
# 联网：直接 clone（bootstrap 独立可跑，不依赖已装好的 rdsh）
bash bootstrap.sh --base ~/Mapp
# 离线：从本地目录或 tarball 装
bash bootstrap.sh --from <目录|rdsh.tar.gz>

# 入口软链（本机脚本已在时，最省事的修法）
ln -sfn ~/Mapp/dsh/Rdsh.sh ~/.local/bin/rdsh
ln -sfn ~/Mapp/dsh/Rdsh.sh ~/Mapp/dsh/rdsh
update-desktop-database ~/.local/share/applications     # 刷图标缓存

# 自更新（会先备份回滚点，校验不过不装）
rdsh selfupdate
```

## 4. rdsh 还能跑时先自查

```bash
rdsh doctor --only entry     # 入口链：rdsh 命令 / <检出>/rdsh / 桌面图标 Exec / PATH
```

## 5. 症状 → 处置

| 症状 | 原因 | 处置 |
|---|---|---|
| `rdsh: command not found` | 入口软链没了 | 第 3 步 |
| 桌面图标点了没反应 | 图标的 `Exec` 路径失效 | 第 3 步 + `update-desktop-database` |
| 起来后会话/设置"全空" | 裸启动没给 `DSH_HOME` | 第 2 步（给对 `DSH_HOME` 再起）；数据仍在 `data/<键>` 里，没丢 |
| 插件全 `failed to import` | home 里的加载链断了（常见于检出被改名/移动） | `rdsh doctor --fix-links --apply`（先 dry-run 看分类） |
| 数据 home 对不上 / "检出不存在" | 检出目录改过名 | `rdsh state rebind <旧路径\|键> <新路径>`；想顺手规范化名字用 `rdsh state rename <目标> --apply` |
| `doctor` 报"检查对象为 0" | 配置/路径不对（不是"一切正常"） | 看 `rdsh base` 的 BASE 是否指对；`RDSH_CONFIG`/`--base` 覆盖 |
