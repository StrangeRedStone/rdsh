## P1 —— 工具链补全

2. `rdsh doctor`：一键只读体检 —— 版本与数据对应关系、软链完整性、插件与权威副本一致性、启动日志报错扫描、磁盘/内存余量、回退基线是否在；输出可粘贴的报告。
3. `rdsh plugins`：包装 `plugin-sync.sh`，让插件维护也走单入口。
4. `rdsh uninstall <版本>`：把检出/数据**移到回收目录**（永不 `rm`），并提示它是否是当前回退基线。
5. `rdsh selfupdate`：从 GitHub 更新工具链自身，带版本校验与备份。
6. **`settings.yaml` 纳入稳定根**：各版本 home 内软链到 `$SHARED_ROOT`（或让 `migrate.sh` 显式携带），使插件开关与配置跨版本不丢。

## 已知风险（未解）

- **无构建记录**：无法判断某个 `lib/` 是哪次构建的产物（源码版本 / 构建时间 / 校验和）。
- **mtime 只是近似方向判断**：`cp -a` 保留时间、手改刷新时间，都可能误导同步方向。
- **网络依赖**：GitHub 不畅时 `fetch` 会失败（已做缓存与 `git ls-remote` 回退）。
- **检查器可能「零检查却报全绿」**：任何新增的自检工具都要打印「检查了几个对象」，并在为 0 时报错。
