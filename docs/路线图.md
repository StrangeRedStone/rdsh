4. ~~**`rdsh restore`**（B4）~~ → **已完成 0.5.0**（见上，含 `backup --snapshot`）。
   原始设想（保留备查）：`--list` / `--from <目录|远端|本地克隆>` / `--type <类>` / `--file <路径>` / `--diff` / `--merge` / `--with-creds`。三类来源要分开；记忆三库是 append-only 语义，默认 `--merge` 而非覆盖；恢复后自动收尾（重链 → `plugin-sync --status` → 断链计数 + `memory_check`，走 doctor）。**会话数据只从本地指定目录恢复，永不联网**。
5. **`rdsh backup --snapshot`**：数据 home 的**增量硬链接快照**（现在 `rdsh backup` 是 `cp -a` 全量，GB 级天天跑会爆盘）+ `--verify` + `--keep N` 保留策略。
6. ~~**`rdsh retire`**（B6）~~ → **已完成 0.5.2**（见上）。

7. **`rdsh uninstall <版本>`**（语义修正）—— 它是 `install` 的**反面**：只移走 `node_modules` 与 `.installed`（回到未安装态），**检出与数据都不动**。退役是 `rdsh retire`，两者别混（旧条目把"删检出/数据"错挂在 uninstall 名下）。
8. ~~**同版本共存编号**（B7）~~ → **已完成 0.5.3**（见上）。
   原始设想（保留备查）：`fetch --dir` / `add` / **`restore`** 都能造出同版本号的第二份检出，而它们现在会映射到**同一个数据 home**（互相写 `workspace.json`/`settings`）。做法：`-2` 后缀全链一致（目录名/数据目录/显示名/账本键），用 `.map` 的 `dir|` 行分数据 home；**不压缩重排次号**（旧引用会静默指向别的对象），删了留墓碑。
9. ~~**`settings.yaml` 迁移携带**（B8）~~ → **已完成 0.6.0**（见上）。

## 已知风险（未解）

- **无构建记录**：无法判断某个 `lib/` 是哪次构建的产物（源码版本 / 构建时间 / 校验和）。
- **mtime 只是近似方向判断**：`cp -a` 保留时间、手改刷新时间，都可能误导同步方向。
- **网络依赖**：GitHub 不畅时 `fetch` 会失败（已做缓存与 `git ls-remote` 回退）。
- **检查器可能「零检查却报全绿」**：任何新增的自检工具都要打印「检查了几个对象」，并在为 0 时报错。
