# 路线图

> 记录待做事项与已知风险。**已完成的实测项**见 [`../CHANGELOG.md`](../CHANGELOG.md)。

## P0 —— 影响"别人能用"

1. **脚本目录自定位回退**
   现状：`MANAGE_ROOT` 默认 `$BASE/dsh`，跨脚本调用（`rdsh patch`、`migrate.sh` 的提示语、`rdsh-restart.sh` 的 `RDSH_BIN`）都按这个根解析。clone 到任意目录后直接跑 `./Rdsh.sh`，子命令会找不到兄弟脚本。
   目标：未显式配置 `MANAGE_ROOT` 时，回退到脚本自身目录（`dirname` + `readlink -f`），同时不破坏 `rdsh base <别的路径>` 的语义。
   注意：软链下 `dirname "$0"` 得到的是**软链所在目录**而非真身目录，需用 `readlink -f` 解。

2. **《DSH 升级与回退指南》**
   完整流程、逐条命令、故障处置、回退演练、发布形态（仓库结构 / README / LICENSE / 版本 tag / 物料清单）。

3. **发布流程**
   GitHub 仓库、LICENSE 决策、首次 release 与 tag、CI 转绿（当前 shellcheck 为咨询性）。

## P1 —— 工具链补全

4. `rdsh doctor`：一键只读体检 —— 版本与数据对应关系、软链完整性、插件与权威副本一致性、启动日志报错扫描、磁盘/内存余量、回退基线是否在；输出可粘贴的报告。
5. `rdsh plugins`：包装 `plugin-sync.sh`，让插件维护也走单入口。
6. `rdsh uninstall <版本>`：把检出/数据**移到回收目录**（永不 `rm`），并提示它是否是当前回退基线。
7. `rdsh selfupdate`：从 GitHub 更新工具链自身，带版本校验与备份。
8. **`settings.yaml` 纳入稳定根**：各版本 home 内软链到 `$BASE/.dsh-shared/`（或让 `migrate.sh` 显式携带），使插件开关与配置跨版本不丢。是「统一插件设置」的附带小基建。

## P2 —— 体验与健壮性

9. **镜像 / 代理友好**：`RDSH_REMOTE`、`RDSH_TARBALL_MIRROR`、`RDSH_PROXY`；网络不畅时一键切镜像。
10. `rdsh fetch` 记录 `tag → commit` 与校验和，落到检出根 `.rdsh-fetch.json`，便于核验同一版本是否被重打过 tag。
11. `rdsh pin`：把某版本钉为默认启动项（现为「最新优先」）。
12. `rdsh logs --rotate` / 大小上限；日志按版本 + 日期切分。
13. bash 补全（`rdsh <TAB>`：子命令、版本号、序号）。
14. `rdsh run <版本> -- <命令>`：在指定版本环境里跑一次性命令（排障用）。
15. **自动化测试**：把「隔离 BASE 下的冒烟」做成可重跑脚本（现在只有 `bash -n` + `--help`）。

## 已知风险（未解）

- **无构建记录**：无法判断某个 `lib/` 是哪次构建的产物（源码版本 / 构建时间 / 校验和）。
- **mtime 只是近似方向判断**：`cp -a` 保留时间、手改刷新时间，都可能误导同步方向。
- **网络依赖**：GitHub 不畅时 `fetch` 会失败（已做缓存与 `git ls-remote` 回退）。
- **检查器可能"零检查却报全绿"**：任何新增的自检工具都要打印「检查了几个对象」，并在为 0 时报错。
