# 能力与命令总表（按脚本）

> **本文件解决的问题**：rdsh 的功能散在多个脚本里，各脚本又各有自己的命令与开关；过去只能读源码才知道"这件事归谁管、证据在哪"。本表**按脚本分段、按表列举**，并给每个能力标注它的**定义**与**证据**。
> **口径**（用户 2026-10-11）：「某功能的实现须提供**符合体系规范的、可使用的定义和证据**」——**定义**＝受理什么/产出什么/边界在哪（机器可读、可被别的脚本消费）；**证据**＝运行后可核验的留痕（报告、清单、日志、校验和）。
> **约定**：`$BASE` ＝ rdsh 的唯一旋钮（`rdsh base`；默认 `$HOME/Mapp`）；`$MANAGE` ＝ 检出根（`$BASE/rdsh`）；`$SUITE` ＝ `$BASE/.dsh-suite`。2026-10-11 起**所有默认根都由 `$BASE` 推导**，配置可以只写一行 `BASE=`。

---

## 0. 术语表（一处定义，他处引用）

| 术语 | 定义 |
|---|---|
| **BASE（基目录）** | rdsh 的**唯一旋钮**：`~/.config/rdsh/config` 的 `BASE=` / 环境 `RDSH_BASE` / 默认 `$HOME/Mapp`。其余根全部由它推导。 |
| **MANAGE（检出根）** | 检出与实例 + rdsh 脚本所在目录；默认 `$BASE/rdsh`，经典布局 `$BASE/dsh`（自动回退）。`Rdsh.sh` **必须**与检出同目录。 |
| **SUITE（稳定根 / `$SUITE`）** | `$BASE/.dsh-suite`：`data/ shared/ backup/ logs/ plugins/ patches/ run/ state/ trash/ debug/ coldD?`。跨版本共享。 |
| **数据 home / DSH_HOME** | `$SUITE/data/<版本>`：一个版本实例的全部本机状态（sessions/storages/settings/credentials/profiles）。 |
| **对象 / 键** | 状态账本里的一行（一个"版本"）；`key` 是它的身份，角色 ∈ `current/baseline/installed/retired`。 |
| **回退基线（baseline）** | 明确保留、用于跨版本退回的那一个对象；**退役时不得是它**。 |
| **实例** | 一个正在跑的 dsh 进程（端口 + PID），由 rdsh 注册；真相是 `ss + /proc`，注册表只是注解层。 |
| **衍生物** | `$MANAGE/<版本>` **之外**、因使用该实例产生的一切产物（会话数据、插件 home 副本、日志…）。 |
| **可再生** | 该衍生物可下载、或可通过程序手段再次生成。 |
| **可用** | ① 程序检查无错误；② 用户使用确认；③ 由**迁移/体检会话**提供证据并写入状态文件（口径见 `设计输入-归档与退役`）。 |
| **定义 / 证据** | 见文首口径。本表每个能力都标这两栏。 |
| **证据不足** | 只有静态检查、没跑实测门 —— 报告里必须显式写出来，不许当"通过"。 |

## 1. 能力总表

| 能力 | 提供者 | 入口命令 | 定义（受理→产出/边界） | 证据 |
|---|---|---|---|---|
| 布局解析 | `Rdsh.sh` | `rdsh base` | 读 env/配置/默认 → 打印 11 个根 | 命令输出本身；`doctor` 第 9 维 |
| 起停实例 | `Rdsh.sh` | `rdsh run/stop/status/restart` | 版本或路径 → 系统单元 + 端口 | `rdsh status`；日志 `$SUITE/logs/web-*.log` |
| 状态账本 | `Rdsh.sh` | `rdsh state list/rebind/rename` | 对象的角色与路径 → 账本 + 流水 | `versions.kv`；`journal.log`；`rdsh state` 输出 |
| 备份/恢复 | `Rdsh.sh` | `rdsh backup/restore/trash*` | 数据/状态 → 快照或回收项 | 快照目录；`trash/index.log` |
| 九维体检 | `doctor.sh` | `rdsh doctor [--only] [--fix-links]` | 全机 11 类对象 → 分级报告 | 报告本身；修复时的 `backup/links-fix-*/links.kv` |
| 跨版本迁移 | `migrate.sh` | `bash migrate.sh <源> <目标>` | 一个版本 → 新版本可用实例 | 迁移日志；回退基线；`compat_check` 报告 |
| 插件一致性 | `plugin-sync.sh` | `--check/--sync/--adopt` | 权威 ↔ 各 home 副本 → 差异表 | `--check` 输出；`backup/plugin-sync-*/` |
| 补丁集 | `patch-manager.sh` | apply/revert/list | 补丁 → 检出改动 | 备份 `backup/patches-*/` |
| 重启+飞轮 | `rdsh-restart.sh` | 由 `reboot` 插件或用户调用 | 延迟重启 + 唤醒续转 | `$SUITE/logs/restart-*.log`；`wake.log.md` |
| 装机自举 | `bootstrap.sh` | `bash bootstrap.sh [--base] [--yes]` | 空机器 → 可用的 rdsh | 安装日志（同脚本落盘） |
| 会话档案 | `plugins.d/session-archive.sh` | `rdsh archive collect/ls/show/export/verify/inject/browse` | 会话数据 → 归档副本 + 索引 | 归档目录 + `verify` 结果 |
| 体检式兼容检查 | `$SUITE/plugins/compat-check` | `compat_check` 工具 / `bin/compat-check.mjs` | 目标版本 → 各维报告 | 报告；`--live` 实测门 |
| 发布 | `tools/publish.sh` | `--stage` | 权威副本 → 仓库快照 | git 提交/标签 |

## 2. `Rdsh.sh` —— 主脚本（门面 + 布局 + 实例 + 账本）

**功能表**

| 功能 | 说明 |
|---|---|
| 布局解析 | 11 个根全部由 `BASE` 推导；env > 配置文件 > 默认 |
| 实例生命周期 | `run/start/stop/restart/status/logs`；后台走 **systemd 用户单元**（`dsh-web-<版本>-<端口>`） |
| 状态账本 | `versions.kv`（唯一权威）+ `journal.log`（只追加流水）+ `回退基线.md`（人读视图） |
| 版本管理 | `fetch/list/migrate/retire/restore`；`retire` 默认只出计划 |
| 备份/回收 | `backup/du/trash/purge`；**永不 `rm`**，一律进回收站 |
| 桥接 | `bridge --spec --json`：把能力清单交给 dsh 侧插件（`rdsh-bridge`） |
| 体检入口 | 转发 `doctor.sh` |

**命令表**（`rdsh help` 的权威版在源码头部；此处按用途分组）

| 用途 | 命令 |
|---|---|
| 看布局 | `rdsh base` |
| 起停 | `rdsh run [版本…]` · `rdsh start` · `rdsh stop [目标\|端口]` · `rdsh restart` · `rdsh status` · `rdsh logs` |
| 版本 | `rdsh list` · `rdsh fetch <版本>` · `rdsh migrate …` · `rdsh retire <目标> [--apply]` · `rdsh restore …` |
| 账本 | `rdsh state` · `rdsh state rebind <旧> <新>` · `rdsh state rename <目标> --apply` |
| 数据 | `rdsh backup/restore/trash/purge/du` |
| 体检/桥接 | `rdsh doctor …` · `rdsh bridge --spec --json` |
| 归档 | `rdsh archive <collect\|ls\|show\|export\|verify\|inject\|browse>` |

**边界**：不做会话内容判断（那是档案/归档的事）；不改上游检出内容（补丁走 `patch-manager.sh`）。

## 3. `doctor.sh` —— 九维体检（+ 断链修复）

**九维**：① 检出 ② 数据 home ③ 软链 ④ 入口链 ⑤ 插件权威↔home ⑥ 状态账本 ⑦ 运行实例 ⑧ 日志 ⑨ 磁盘内存 ⑩ 配置解析。

| 开关 | 作用 | 证据 |
|---|---|---|
| `--only <维>` | 只跑某几维（如 `links`、`config`） | 该维报告 |
| `--fix-links` | 断链修复；**默认干跑**，`--apply` 才改 | 改前写 `backup/links-fix-<ts>/links.kv`（**可还原清单**） |
| `--quiet` | 只出汇总 | 汇总一行 |

**已知边界**（2026-10-11 实测）：① 它**读全量追加式日志**，历史报错会一直出现在 warn 里（判"良性"要看行号是否落在本次启动块）；② 账本第 12/14 列（data/settings **回声**）`state rebind` 不覆盖，需手工改；③ home 的 **6 条资产链**（`AGENTS.md`/`skills`/`lessons.md`/`facts.md`/`backlog.md`/`.agent-presets`）**不在它的修复范围**，搬迁后必须手工补（`plugins/setup.sh` 只管插件链）。

## 4. `plugin-sync.sh` —— 插件权威 ↔ 各 home 副本

| 命令 | 作用 |
|---|---|
| `--check` | 只比差异，列"home 缺/版本旧/代码不一致" |
| `--sync <版本>` | 权威 → home（**保留目标独有文件**，不覆盖） |
| `--adopt <版本>` | 反方向（home → 权威），有方向守卫 |

**证据**：每次同步写 `backup/plugin-sync-<ts>/`。
**已知边界**："旧 home 缺较新才有的插件"属**良性**（回退用的旧 home 不需要补），报告里明确写了。

## 5. `migrate.sh` / `patch-manager.sh` / `rdsh-restart.sh` / `bootstrap.sh`

| 脚本 | 功能 | 关键开关 | 证据 |
|---|---|---|---|
| `migrate.sh` | 跨版本迁移：备份 + 建链 + 探针 + 回退基线 | `<源> <目标>` | 迁移日志 + 回退基线 + `compat_check` 报告 |
| `patch-manager.sh` | 上游补丁集 apply/revert/list | `apply/revert` | `backup/patches-<ts>/` |
| `rdsh-restart.sh` | 延迟重启 + 唤醒续转（必须 `systemd-run --user` 拉起） | `--delay`、`--wake` | `$SUITE/logs/restart-*.log` + `wake.log.md` |
| `bootstrap.sh` | 自举安装（装机）：clone/离线包 + 入口软链 + BASE 探测 | `--base/--dir/--from/--yes/--bin-dir/--dry-run` | 安装日志；`--dry-run` 只打印计划 |

**`bootstrap.sh` 的行为约定**（2026-10-11 起）：**未指定 BASE 且是交互终端 → 先问一句**（回车用默认）；`--yes` 跳过；非终端输入保持原行为（不改变既有自动化）；默认检出位置 `$BASE/rdsh`（经典 `$BASE/dsh`）。

## 6. `plugins.d/`（外部能力）与 `tools/`

| 脚本 | 能力 | 定义 | 证据 |
|---|---|---|---|
| `plugins.d/session-archive.sh` | 会话历史档案库 | 会话数据 → 归档副本（**只复制，不动原数据**）；落点 `$BASE/sessionsD/sessions`（与 `coldD` 并列） | 归档目录 + 索引；`verify [--rebuild-index]`；`export` 出可读 JSONL |
| `tools/publish.sh` | 权威副本 → 仓库快照（单向） | `--stage` | git 提交/标签 |
| `tools/smoke-*.sh` | 各子命令冒烟 | 只读/干跑为主 | 脚本自身的输出 |

**外部能力协议**：脚本用 `--manifest` 自述（能力清单）；`rdsh` 用 `bridge --spec` 汇总后交给 dsh 侧插件（`rdsh-bridge` 一个能力注册一个工具）。**新增能力只要进 spec 就能被 dsh 看见**。

## 7. 维护约定（写这个文档的"元规则"）

1. **新增/改动一个能力**：本表两处都要动——§1 总表加一行（含**定义**与**证据**），对应脚本那一节加命令行；
2. **悬空即错误**：能力在本表里没有"证据"栏 ⇒ 视为未完成；
3. **"证据不足"必须写出来**（例：`compat_check` 没跑 `--live` 时结论是"证据不足"而不是"通过"）；
4. 文档随脚本走：**脚本与本文档不同步时，以脚本源码头部为准**，并回头补本表。
