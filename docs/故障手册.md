# 故障手册

> 每条都对应一次真实处置。原则：先量出对象与数量，再下结论。

## 1. 升级/拷会话后，UI 里显示「未分组」

**原因**：`WorkspaceRegistry` 启动时读 `storages/workspace.json`；`initialized=true` 时只重建索引，**不新增成员**，手工拷进来的会话永远进不了工作区。

**处置**（**必须先停掉该版本实例**）：

```bash
rdsh status                    # 确认实例状态
bash reindex-workspaces.sh 0.1.6-alpha.1 --dry-run   # 先看计划
bash reindex-workspaces.sh 0.1.6-alpha.1             # 真跑（会先备份 workspace.json）
```

运行中的进程持有内存状态，退出时会写回 `workspace.json`，**覆盖**这里的修改。

## 2. 插件在新旧版本间分叉

**症状**：同一个插件在新 home 与旧 home 各一份，修一处另一处不变。

**处置**：

```bash
bash plugin-sync.sh --check            # 只读：列出各 home 与权威副本的差异
bash plugin-sync.sh --sync 0.1.6-alpha.1   # 权威 → home（先备份被覆盖的目录）
```

**若 `--sync` 说"目标更新，已跳过"**：说明 home 那份比权威副本新（可能你在 home 里直接改过）。两条出路：
- `plugin-sync.sh --adopt <版本>`：把那份**反向提升**为权威（推荐，别丢改动）；
- `plugin-sync.sh --sync <版本> --force`：确实要覆盖。

## 3. 写入没落到共享文件（软链被顶掉）

**症状**：内容看着对，但从此刻起该版本 home 里是一份**分叉副本**。

**处置**：写完查三样——

```bash
ls -la $DSH_HOME/facts.md                                  # 1) 应仍是 lrwxrwxrwx
stat -Lc '%i %s %n' $BASE/.dsh-shared/facts.md $DSH_HOME/facts.md   # 2) 同 inode（-L 必须）
diff $BASE/.dsh-shared/facts.md $DSH_HOME/facts.md && md5sum ...    # 3) 内容一致
```

根因通常是「临时文件 + rename」的原子写把软链替换成了普通文件。正确修法是让写入方解析真实路径，而不是放弃外置。

## 4. 重启断在半路 / 新实例被一起杀掉

**原因**：重启脚本若运行在 DSH 自己的子进程里，会被它自己触发的关停流程杀掉；新实例若不在独立 cgroup，也会随旧进程一起死。

**处置**：

```bash
bash rdsh-restart.sh --dry-run     # 只打印计划，随时可安全跑
bash rdsh-restart.sh --probe       # 完整演练投递链路（不 kill、不启动）
bash rdsh-restart.sh               # 真重启
```

逃生舱会自动把自己投递到 `systemd-run --user` 单元；日志在 `$BASE/.dsh-logs/restart-<ts>.log`。

## 5. `rdsh start` 报端口 3080 被占用

`rdsh start` 见到端口被占会直接 die（设计如此，不抢别人的实例）。要么先用 `rdsh-restart.sh` 重启，要么先停掉占用者。**不要**用 `pkill -f` 清理——会自匹配误杀。

## 6. 日志里有访问 token

- `rdsh logs` 显示时会自动打码；日志目录 `700`、文件 `600`。
- **分享/发布/打包前不要带上任何日志**（`$BASE/.dsh-logs/` 可能有真实 token 明文）。

## 7. 升级后补丁没了

升级换了检出目录，补丁需重放：

```bash
rdsh patch list
rdsh patch status
rdsh patch apply --dry-run
rdsh patch apply
```

冲突时它会**停手并回滚本次已应用的补丁**，不会把检出改坏。

## 8. 检查器给"全绿"，其实什么都没查

**症状**：脚本没报差异，但它根本没检查到对象（空循环给出自信的 ✅）。

**处置**：看它打印的**对象计数**。任何检查器都必须能区分「零发现」与「零检查」；数量为 0 时应报错或显著警告，而不是给出通过结论。自查手法：用一个人为损坏的样本跑一遍，确认它真能报出来。

## 9. 同步/覆盖类工具把更新的那份盖回去了

**判据**：「内容不同」≠「该被覆盖」。任何单向覆盖都隐含一个方向假设，必须显式化并加守卫（mtime / 校验和 / 构建记录），覆盖前先备份。遇到工具做了超出预期的事（比如一口气覆盖多个对象），**停下核对，不要继续往下做**。

## 10. 「优雅降级」掩盖了时序 bug

**判据**：降级后的行为是否与正常路径**等价**？不等价（缺预设、缺服务、少一个世界）就该**失败退出 + 重试**，而不是降级。降级路径会退回到一个已知错误的行为时，它不是在容错，是在把时序 bug 掩盖成一次静默的错误结果。
