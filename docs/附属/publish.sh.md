# tools/publish.sh —— 维护者工具：本机 → 发布仓库（附属）

> **维护者工具**，不是运行时组件。方向**单向**：本机（权威）→ 仓库（发布快照）。

- **能力**：按**显式白名单**逐个文件搬运（绝不通配扫目录，避免把 6G+ 检出带进仓库）。
- **提供的证据/守卫**：搬运**之前**跑隐私守卫（`scan-secrets.sh`），有 error 就不许继续；结束后打印 `git status` 并提示未跟踪文件。
- **变量**：`RDSH_PUBLISH_FROM`（源，默认从 rdsh 的 `BASE` 推导）、`--from <目录>`、`--stage`。
- **示例**：`bash tools/publish.sh --stage` → 核对 `git status` → `git add -A && git commit && git push`。
- **边界（2026-10-12 修的两处静默失败）**：① 默认源曾写死 `~/Mapp/dsh`；② **隐私守卫曾被静默跳过**——`SCAN` 在参数解析前就按默认源算好路径，`--from` 换了源而守卫路径没换，找不到就"未扫描"。现已把 `SCAN` 解析挪到源定下来之后，**发布前必扫**。

## 维护者：本机工作目录 ↔ 发布仓库

本仓库是**发布快照**；日常在用的真身放在**检出根**（默认 `$BASE/rdsh/`）。那个目录同时还放着 dsh 的检出（上游代码，6G+），**所以绝不能把整个目录当仓库**。

两者关系是**单向**的：本机是权威，仓库只是发布目标。

```bash
# 1) 在 $BASE/rdsh 里改脚本（跟平时一样）
# 2) 看差异（只读，有差异时退出码 1）
bash tools/publish.sh --check
# 3) 把白名单文件集中进仓库
bash tools/publish.sh --stage
# 4) 提交并推送
git add -A && git commit -m "..." && git push
```

`tools/publish.sh` **只搬运写死在白名单里的那 6 个脚本**，不通配扫目录 —— 所以本机工作目录里的检出（上游代码）永远不会被带进仓库。
