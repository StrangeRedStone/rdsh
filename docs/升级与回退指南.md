# DSH 升级与回退指南

> 面向：用 **rdsh** 在这台机器上管理多个 DeepSeek Harness（dsh）版本的人。
> 配套：[README](../README.md)（工具总览）、[架构](架构.md)（三层资产模型）、[故障手册](故障手册.md)（通用故障）、[路线图](路线图.md)。
> 本文路径用「变量名」表述，本机实际取值见 §9。

## 0. 一分钟版

- **升级** = 下载新检出 → 预演迁移 → 真迁移 → 起新版本 → 验收。
- **回退** = 用**旧版本**起回去（旧 home 与旧检出一直在，从不删除）。
- **升级前必做**：备一次数据 + 看清回退基线 + 确认新版本能 install。

## 1. 三个东西要分清

| 概念 | 变量 | 装什么 | 升级时怎么变 |
|---|---|---|---|
| **检出** | `$MANAGE_ROOT/deepseek-harness-<版本>` | dsh 源码（pnpm 安装产物） | 换一个新目录 |
| **数据根** | `$DATA_ROOT/<版本>`（即 `$DSH_HOME`） | sessions / storages / settings.yaml / plugins | 迁移 + 复制 |
| **作者资产** | `$SHARED_ROOT` | skills / lessons.md / facts.md / backlog.md / AGENTS.md | **不搬**，各 home 内是软链 |

> 细节见 [架构](架构.md) 的「三层资产模型 L1/L2/L3」。**记住这条就够**：会话数据要搬，作者资产不搬（软链），插件靠权威副本同步。

## 2. 升级前检查单

- [ ] 看现状：`rdsh status`（在跑哪个版本、数据在哪）
- [ ] **备份**：`rdsh backup <当前版本>`（落到 `$BACKUP_ROOT`）
- [ ] 看回退基线：`cat $BACKUP_ROOT/回退基线.md` —— 记下「源 / 备份目录 / 还原命令」
- [ ] 磁盘与内存：`df -h ~ && free -h`（新检出要 pnpm install）
- [ ] 网络：`rdsh fetch --list` 能列出远端版本（GitHub 不通就先解决网络）
- [ ] **新版本构建前置**：Node 头文件（见 §5.1，这一条曾让 install 失败）

## 3. 升级流程（逐条命令）

### 3.1 下载并安装新版本

`@bash
rdsh fetch --list                  # 列远端可用版本（10 分钟磁盘缓存）
rdsh fetch 0.1.6-alpha.1 --install # 下载 + pnpm install + 打标
# 也可分两步：rdsh fetch <版本>   然后   rdsh install <版本>
`@

> `install` 成功后再往下走。**这一步失败不要去迁移**（迁移器不负责安装）。

### 3.2 预演迁移（只读，随时可跑）

`@bash
bash migrate.sh 0.1.3 0.1.6 --dry-run
`@

输出里要看的四件事：**备份目录**、要搬的 L1、要建的 L2 软链、L3 插件来源，以及**探针结论**（对新检出有没有发现断点）。

### 3.3 停实例

在跑 DSH 的那个终端按 **Ctrl-C**（或 GUI 菜单「结束 DSH」）。

### 3.4 真迁移

`@bash
bash migrate.sh 0.1.3 0.1.6
`@

七步：备份 → 建 L2 软链 → 搬 L1 → 装 L3 插件 → 探针 → （4b）置 `initialized=false` → 追加回退基线。
**全程无 `rm`，幂等，可重跑。**

### 3.5 起新版本

`@bash
rdsh 0.1.6        # 或直接 rdsh 然后选序号
`@

### 3.6 验收 → 见 §6。

## 4. 回退流程

### 4.1 快速回退（最常见，30 秒）

旧 home 与旧检出**从头到尾没被删过**，所以：

`@bash
# 停新实例（Ctrl-C），然后
rdsh 0.1.3
`@

回退到旧版本会用它**自己那份旧数据**（新版本里做的事不会自动带回去）。

### 4.2 带数据回退（新版本已写数据且要回到旧数据）

1. 打开 `$BACKUP_ROOT/回退基线.md`，找到对应那次升级的**备份目录**与**还原命令**；
2. 停实例；
3. 从备份目录恢复 `sessions/ storages/ settings.yaml .credentials.yaml` 到目标 home；
4. **永不 `rm`** —— 被覆盖/出错的数据先 `mv` 到回收目录，并在输出里记下路径。

### 4.3 回退后还要补两件事

- **插件**：旧 home 的插件副本可能缺最新修复 → `bash plugin-sync.sh --check`，必要时 `--adopt`（把 home 那份反向提升为权威）或 `--sync`。
- **工作区归属**：若手工拷过会话 → `bash reindex-workspaces.sh <版本>`（**必须先在实例停机状态**）。

## 5. 升级特有的坑（都是实测踩出来的）

### 5.1 `rdsh install` 因缺 Node 头文件失败

- **症状**：编译 `native/system`（flock 的 N-API 模块）时报找不到 `/usr/include/node`。
- **根因**：NodeSource 装的 `nodejs` 不含头文件包。
- **修法**：`sudo dnf install -y nodejs-devel` —— 装**同版本、同 epoch** 的头文件包，别让它顺带升级 Node 本身。
- 注意：这是**上游新增的构建前置条件**，与迁移设计无关；每次大版本升级前都值得先确认。

### 5.2 核对类工具的默认值不能硬编码

`compat_check` 曾换版本后仍对着**旧检出**下结论、还报 ✅。
现状：默认改为按 `process.cwd()` 自动探测（rdsh 从检出根启动）；探测失败才回退并在报告头标注。

### 5.3 插件在版本间分叉（L3）

`migrate.sh` 会把 `plugins/` 复制到新 home —— 于是同一插件在新旧 home 各一份，**修一处另一处不变**。
对策：单一权威副本 `$PLUGIN_ROOT` + `plugin-sync.sh --check/--sync/--adopt`（带 mtime 方向守卫）。

### 5.4 手拷会话显示「未分组」

`WorkspaceRegistry` 只在 `initialized=false` 时按会话 header 的 cwd 重新归组。
对策：`reindex-workspaces.sh`（脚本会先备份 `workspace.json`；**实例在跑就拒绝执行**）。
`migrate.sh` 的 4b 步已自动置 `false`，多数情况无需手跑。

### 5.5 `settings.yaml` 不跨版本延续

它是每版本一份的实文件，插件开关与配置**升级会丢**（见[路线图](路线图.md) P1#7）。升完记得重配。

### 5.6 端口被占 / 重启

`rdsh start` 见端口被占会直接退出（设计如此）。用 `bash rdsh-restart.sh --dry-run|--probe|<真跑>` 安全重启；**永不用 `pkill -f`**。

## 6. 升级后验收清单（不看 UI 也能核）

- [ ] `rdsh list` / `rdsh status`：版本齐全、数据指向新 home
- [ ] 实例真的用的是新数据根：
      `tr '\\0' '\\n' < /proc/<pid>/environ | grep DSH_HOME`
- [ ] 启动日志**没有** `failed to import`：`grep -i 'failed to import' $LOG_DIR/web-<版本>.log | tail`
- [ ] 插件都在：`bash plugin-sync.sh --status`
- [ ] 记忆库：`memory_check`（插件工具）
- [ ] 记忆库软链仍指对：`ls -la $DSH_HOME/facts.md` → 应指向 `$SHARED_ROOT/facts.md`
- [ ] 会话能打开、工作区归属正确
- [ ] 在检出根跑 `compat_check`（真上下文）

> **验收要看日志与文件，不要只看 UI**。UI 正常不代表插件都加载了。

## 7. 回退演练（建议每次大升级后做一次）

演练 ≠ 真回退，只是**确认退路还在**：

`@bash
rdsh list                          # 旧版本检出与数据都还在？
cat $BACKUP_ROOT/回退基线.md        # 最近一次的还原命令可用？
rdsh 0.1.3                         # 真起一次旧版本，看数据在、插件在
# 确认无误后再起回新版
`@

## 8. 命令速查

| 目的 | 命令 |
|---|---|
| 看现状 | `rdsh status` / `rdsh list` |
| 备数据 | `rdsh backup <版本>` |
| 看退路 | `cat $BACKUP_ROOT/回退基线.md` |
| 下载 | `rdsh fetch --list` / `rdsh fetch <版本> [--git]` |
| 安装 | `rdsh install <版本>` |
| 预演迁移 | `bash migrate.sh <源> <目标> --dry-run` |
| 迁移 | `bash migrate.sh <源> <目标>` |
| 启动 | `rdsh <版本>` |
| 安全重启 | `bash rdsh-restart.sh [--dry-run|--probe]` |
| 插件一致性 | `bash plugin-sync.sh --check|--sync|--adopt` |
| 重建工作区归属 | `bash reindex-workspaces.sh <版本>`（先停实例） |
| 补丁重放 | `rdsh patch list|status|apply|revert` |
| 看日志 | `rdsh logs [-f]`（显示时自动打码 token） |

## 9. 本机当前取值（2026-09-19 目录收敛后）

`@
MANAGE_ROOT = ~/Mapp/dsh                     # 脚本 + 检出
DATA_ROOT   = ~/Mapp/.dsh-suite/data          # 各版本 DSH_HOME
SHARED_ROOT = ~/Mapp/.dsh-suite/shared        # 作者资产（软链源）
BACKUP_ROOT = ~/Mapp/.dsh-suite/backup        # 备份 + 回退基线.md
LOG_DIR     = ~/Mapp/.dsh-suite/logs
PLUGIN_ROOT = ~/Mapp/.dsh-suite/plugins       # 插件权威副本
PATCHES     = ~/Mapp/.dsh-suite/patches
`@

配置文件：`~/.config/rdsh/config`（**唯一旋钮 BASE 的逐项覆盖**；优先级：环境变量 > 配置文件 > 默认）。
改了这份配置，所有 rdsh 脚本会一起跟随（同一套解析）。
