# 架构

> 本文说明 rdsh 的结构性决策与取舍。命令细节见 [`../README.md`](../README.md)。

## 1. 一句话

用 **「单一旋钮 BASE + 三层资产模型 + 版本化数据根」** 把「一台机器并存多个 dsh 版本」从高风险手工搬迁，变成有工具、有探针、有回退基线的常规操作。

## 2. 单一旋钮 BASE

所有路径由一个 `BASE` 派生，解析优先级：

```
环境变量 RDSH_BASE  >  ~/.config/rdsh/config  >  默认 $HOME/Mapp
```

配置文件是**纯 `KEY=VALUE`，不会被 source**（避免执行任意代码），只按行取值。派生关系：

| 派生变量 | 默认 | 用途 |
|---|---|---|
| `MANAGE_ROOT` | `$BASE/dsh` | 检出根（本仓库也在这一层） |
| `DATA_ROOT` | `$BASE/.dsh` | 每版本数据根 |
| `BACKUP_ROOT` | `$BASE/.dsh-backup` | 备份 + `回退基线.md` |
| `SHARED_ROOT` | `$BASE/.dsh-shared` | 与版本无关的作者资产 |
| `LOG_DIR` | `$BASE/.dsh-logs` | 启动日志 |

`rdsh base <路径>` **只改指向、不搬任何数据**；这是刻意的（P1：不替用户做不可逆决定），代价是换基目录后旧数据仍在原处，需用户自行迁移。

## 3. 三层资产模型

迁移时不同类型的资产待遇不同，这是整个工具链的核心抽象：

| 层 | 内容 | 待遇 | 为什么 |
|---|---|---|---|
| **L1 上游数据** | `sessions/` `storages/` `settings.yaml` `.credentials.yaml` | **原样搬**，交给新版自己迁移 | 会话格式有 `v0→v1→v2(→v3)` 迁移链，只有新版知道怎么转 |
| **L2 作者资产** | `skills/` `lessons.md` `AGENTS.md` `.agent-presets/` `facts.md` `backlog.md` | **不搬**：放在稳定根，各版本 home 内只建**软链** | 内容与版本无关；复制就会分叉 |
| **L3 插件** | `plugins/` + `profiles/web/cordis.patch.yml` | **复制 + 重建 symlink**，另有权威副本与同步器 | 插件按检出版本编译，跨版本共享二进制可能不对；但代码只有一份真身 |

> 配套的 `compat_check` 插件会在升级后出「API 断点报告」，补上 L3 的兼容性缺口。

## 4. 版本化数据根

每个版本一个 `DSH_HOME`（`$BASE/.dsh/<版本号>/`）。原因不是洁癖：把不同版本的会话/存储塞进同一个 `~/.dsh` 会触发会话日志偏移之类的崩溃。版本号从检出 `package.json` 读取，而不是目录名——目录名可以任取（`--dir`），版本号才是事实。

## 5. 软链接共享（L2）

稳定根持有真身，各版本 home 内是软链。**写入验收要查三样**，缺一不可：

1. 写完**仍是软链**（`ls -la` 应为 `lrwxrwxrwx … -> …`）；
2. 两侧**同一 inode**（`stat -Lc '%i %s %n'`，GNU `stat` 默认 **lstat**，必须显式 `-L`）；
3. 两侧**内容一致**（`diff` 为空 + `md5sum` 相同）。

为什么第 1 条单独要查：「写临时文件再 `rename`」的原子写会把**软链本身**替换成普通文件——内容看着对，但从此刻起该 home 里就是一份分叉副本。

## 6. 插件权威副本（L3）

```
$BASE/dsh-plugins/<插件名>/          ← 唯一权威副本（canonical）
$DSH_HOME/plugins/<插件名>/          ← 各版本 home 里的副本，可被 --sync 覆盖
```

**比对口径**：比代码（`package.json` / `lib/` / `src/`），**排除** `node_modules/`（指向具体检出的软链，天生按版本不同）与 `contracts.json`（记录「本 home 验证过哪些版本」，本就不同）。

**方向守卫**：`--sync` 不能只比「内容是否相同」——「不同」不代表「该被覆盖」。它会比较两侧最新 mtime，目标更新则**默认跳过**，并给出两条出路：`--adopt <版本>`（反向提升为权威）或 `--force`（确实要覆盖）。

## 7. 补丁机制

升级会**换检出目录**，所以打在内置包上的改动必须有办法重放：

```
$BASE/dsh-patches/
├── manifest.yaml        # 补丁集清单：顺序、涉及路径、基线、重建命令
└── <集名>/0001-*.patch
```

`patch-manager.sh` 在 apply/revert 前把涉及文件备份到 `$BASE/.dsh-backup/patches-<时间戳>/`；**任一补丁失败就回滚本次已应用的补丁并退出**，绝不半应用把检出改坏。

## 8. 多实例与安全重启

**0.3.0 起 `Rdsh.sh` 自己管实例**：`rdsh run` 默认把实例投递到 `systemd-run --user` 单元（脱离终端与 DSH 的 cgroup），`rdsh stop` 负责停。`rdsh-restart.sh` 仍是"重启当前实例"的编排者，但它现在调用的正是同一套 `run/start` 原语。

### 8.1 实例识别的两层

- **真相层**：`ss` + `/proc`。PID、cwd、`DSH_HOME` 都现场读；"是不是我们的 dsh web"由 `is_dsh_web_pid` 判定（cmdline 是 web 入口 **且** cwd 是已管理检出或名字像 dsh 检出）。
- **注解层**：`$BASE/.dsh-suite/run/instances/<端口>.kv`，只补 `ss` 查不到的字段（kind、debug id、systemd 单元名、日志、启动时间）。注解丢了不影响识别；过期条目自动退休到 `run/stale/`（不 `rm`）。

这样"新版本管住没登记过的旧实例"是天然成立的，不需要历史迁移。

### 8.2 `rdsh stop` 的约束（都实测换来的）

1. **归属校验是唯一红线**：进程过不了 `is_dsh_web_pid` 就绝不碰，**没有 `--force` 能覆盖它**；禁用 `pkill/pgrep -f`；**绝不发 `-9`**。
2. **托管实例优先 `systemctl --user stop <unit>`**：一次收掉整个 cgroup（含 pnpm 包装进程与子进程），比单发 SIGTERM 干净。未托管才回落 SIGTERM + 等端口释放 + 补刀包装进程（仍要过归属校验）。
3. **自杀防护 + 逃生舱**：目标是本进程的祖先时（就是你在用的那个实例），非交互环境直接拒绝；`--force` 确认后把自己投递到一次性 `systemd-run` 单元并延迟执行（`--delay`），让调用方先把当前回合落盘。
4. **绝不强杀**：等端口释放超时就报错收手，交给人处理。
5. 默认停"**端口最大的那一个**"（后进先出，与 `run` 的端口递增对称）；`--all` 从大到小。

### 8.3 `rdsh run`（多实例）

- 默认**后台化**：`systemd-run --user --unit=dsh-web-<版本>-<端口>`。新实例的 cgroup 与 `dsh-subprocess-<pid>-<hash>.scope` 平级，不在 DSH 关停时的 managed range 内；否则新进程会随旧进程一起被杀。`--foreground` 回到占终端的老行为。
- **单元内部一律前台**（`DSH_LAUNCH_DETACHED=1` 兜底），结构上排除"套两层单元"。
- 端口**默认加一**（在跑实例最大端口 +1）；同一 `DSH_HOME` **拒绝双开**（多开会互相写 `workspace.json`/`settings`，会话级 flock 只保护单会话）。同版本多开走 `rdsh debug`。
- **环境变量要显式转发**：systemd 用户单元只继承 `PATH`/`HOME`/`XDG_RUNTIME_DIR`，不继承自定义变量，所以 `RDSH_*`/`DSH_*` 一律 `--setenv`。

### 8.4 `rdsh-restart.sh` 与逃生舱

如果脚本是从 DSH 自己的子进程里被拉起的（例如 agent 的 `bash` 工具），它会先把「自己」重新投递到 systemd 单元再退出——否则会被它自己触发的关停流程一起杀掉，重启做到一半就断。`--probe` 可完整演练投递链路而**不真的 kill**。

它调用 `rdsh start` 时固定带 `--foreground --takeover --port "$PORT"`：`--foreground` 防套两层单元、`--takeover` 放行"同一 home 已在跑"（重启本来就会先停掉它）、`--port` 钉住端口（否则会被"最大端口+1"挪走）。

## 9. 调试环境（可丢弃沙箱）

`rdsh debug` 给"试一个新版本/新配置，又不想碰正式数据"提供正路：

```
$BASE/.dsh-suite/debug/<id>.env     # 清单（600）：id/版本/检出/创建时间/assets/creds
$BASE/.dsh-suite/debug/<id>/        # 就是 DSH_HOME，默认**完全空**
```

- **默认全新**：不播种 `settings`、不链作者资产、不链凭据。实测首启后只剩 dsh 自己的 `.anonymous-user-id`/`profiles`/`storages` + 一个空凭据文件，**0 个软链**。
- **按需加料**：`add --assets`（软链作者资产）、`--creds`（软链凭据，读写同一份）、`--copy-creds`（独立复制 + `chmod 600`——dsh 对凭据文件有"不得有组/其他位"的硬校验）；`detach` 反向摘掉，只挪软链、**真身不动**。
- **删除**：`rm` 先停实例 → home + 清单整体挪进回收目录 → 打印还原命令；**永不 `rm`**，且硬白名单只认 `$BASE/.dsh-suite/debug/` 下带清单的环境。
- **id 必须以字母开头**，保证 `rdsh run <版本>` 永不撞上沙箱名。

## 10. 设计原则（P1）

1. **只检测、只留痕、只放行** —— 不替用户做不可逆决定，也不阻止用户做。
2. **永不 `rm`** —— 删除一律先 `mv` 到回收目录，并在输出里说明去了哪。
3. **幂等 + `--dry-run`** —— 任何写操作都能安全重跑；不覆盖已有数据，冲突只警告。
4. **单一旋钮 / 单一权威** —— 同类东西只有一处真相。
5. **每个动作留证据** —— 备份目录带还原说明，基线进 `回退基线.md`，探针出报告。
6. **慢操作要能被打断** —— 网络操作给超时、可缓存、失败给可操作的下一步建议。

## 11. 诚实边界

- `plugin-sync` 的方向判断基于 **mtime**，是近似值；更稳的「构建记录（源码位置 + 构建时间 + 校验和）」尚未实现。
- 插件权威副本「谁最新」目前由人（或 `--adopt`）决定，**没有自动构建流水线**。
- `reindex-workspaces.sh` 依赖上游 `initialized=false` 重扫机制；上游若改，此脚本需跟着改。
- `settings.yaml` 不在稳定根（见路线图），跨版本升级会丢插件配置。
- 脚本假定自己位于 `$BASE/dsh/`；跨脚本调用按此解析，未做脚本目录自定位回退（见路线图 P0）。
- `rdsh stop` / `rdsh-restart.sh` 的停/起逻辑目前是**两处实现**（语义一致，都要求 cwd+cmdline 匹配归属），尚未收敛为一处；这是 0.3.0 明确的遗留项。
- 调试环境里 `AGENTS.md` / `.agent-presets` 是否热生效**未实机验证**（`skills` 与 `.credentials.yaml` 有热重载证据）。
